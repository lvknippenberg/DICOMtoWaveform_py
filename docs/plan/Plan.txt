# Implementation plan: robust Doppler envelope detection from single-frame DICOM images

## 0. Project objective

Implement and benchmark a collection of **non-deep-learning Doppler envelope detectors** for cardiac ultrasound DICOM images.

The system must:

1. Accept a **single-frame DICOM image**.
2. Automatically identify and isolate the Doppler spectral region.
3. Support both:

   * conventional spectral Doppler / PW or CW Doppler;
   * tissue Doppler / TDI.
4. Preferably use a **common envelope-extraction framework** for both.
5. Produce:

   * positive/upper envelope;
   * negative/lower envelope where present;
   * optionally a signed envelope;
   * confidence/quality measures.
6. Be robust to substantial variation in SNR.
7. Be evaluated against manually annotated reference envelopes supplied by the user.
8. Make the individual algorithmic stages configurable so that the experiment can determine which components matter.
9. **Do not use deep learning.**
10. Keep the implementation reproducible and interpretable.

The primary hypothesis to test is:

> **For rendered single-frame DICOM images, a 2-D image-based method combining adaptive intensity normalization, robust binarization, morphological cleanup, connected-component analysis and constrained boundary tracking will be more robust across SNR than purely spectrum-by-spectrum maximum-frequency estimators.**

A secondary hypothesis is:

> **At high SNR, classical integrated-power-spectrum methods such as GM/MGM/SNSI/QIA will perform competitively or better, while at low SNR a spatial-temporal image method will provide a more stable envelope.**

A third hypothesis is:

> **The optimal detector may differ less between spectral Doppler and tissue Doppler than expected if the algorithm is formulated as generic detection of a Doppler-energy region followed by extraction of its outer boundary, but parameter settings—especially smoothing, thresholding and expected slope/velocity constraints—will likely need to differ.**

---

# 1. Important input constraint

The input is **a single rendered DICOM frame**, not raw ultrasound data.

This distinction is critical.

Do **not** assume access to:

* IQ data;
* RF data;
* Doppler audio;
* complex baseband data;
* original FFT bins;
* ultrasound-system noise estimates;
* acquisition-time SNR;
* PRF metadata unless actually present in the DICOM.

Therefore, algorithms in the literature that operate directly on the Doppler power spectrum should be implemented as **image-domain approximations** where possible.

The implementation should explicitly distinguish:

### Class A — spectrum-derived methods

Methods that can be reconstructed approximately from each vertical image column if pixel intensity is proportional/monotonic with Doppler power.

### Class B — image-domain methods

Methods designed to operate directly on a rendered spectrogram.

Class B is likely to be more appropriate for the final application.

# 6. Estimator 1 — simple fixed threshold

Implement this first as the baseline.

For each column \(x\):

1. normalize intensity;
2. determine threshold \(T\);
3. find the highest \(y\) satisfying

$$
I(x,y)>T.
$$

For bidirectional Doppler, independently find:

$$
y_\mathrm{upper}(x)
$$

and

$$
y_\mathrm{lower}(x).
$$

### Variants

Test:

```text
global threshold
percentile threshold
threshold relative to image maximum
threshold relative to local column maximum
```

Example:

$$
T = P_{q}(I)
$$

where \(P_q\) is an image-intensity percentile.

### Why include it?

Not because it is expected to win.

It establishes:

* how difficult the problem is;
* how much SNR variation affects the result;
* whether sophisticated methods are actually needed.

---

# 7. Estimator 2 — Otsu thresholding

Implement:

### Global Otsu

Find threshold \(T\) maximizing between-class variance.

Then:

```text
image
 → Otsu
 → binary mask
 → morphology
 → boundary
```

This is particularly relevant because Otsu-based methods have been used for Doppler envelope extraction, including the Latham work and related image-processing literature. Latham's published method is based on an Otsu/morphological approach to Doppler spectrogram images. ([PubMed][3])

### Variants

Test:

* global Otsu;
* Otsu after Gaussian smoothing;
* Otsu after background subtraction.

Do not initially use adaptive/local Otsu unless the global version is clearly inadequate.

# 8. Estimator 3 — percentile / integrated-power method

Implement a spectrum-style estimator using each image column.

Treat grayscale intensity as a proxy for spectral power:

$$
P_x(y)=I(x,y).
$$

For each column, calculate cumulative power:

$$
C_x(y)=
\frac{\sum_{k \leq y}P_x(k)}
{\sum_k P_x(k)}.
$$

Estimate the envelope as the \(p\)-percentile point.

Test:

```text
p = 90%
p = 95%
p = 97%
p = 98%
p = 99%
```

Do not assume that one percentile is optimal.

The purpose of the experiment is to determine:

$$
p^* = \arg\min_p E(\hat e_p,e_\mathrm{ref}).
$$

Important:

The percentile should be optimized **only on training/development images**, not on the final test set.

---

# 9. Estimator 4 — Geometric Method (GM)

Implement the classical **Geometric Method**.

Reference:

Kathpalia et al. describe GM as one of the established approaches and combine a modified form of it with SNSI. ([PubMed][1])

For each spectrum:

1. calculate integrated power;
2. normalize cumulative power;
3. construct the characteristic geometric reference;
4. find the point of maximum deviation;
5. map that point to the maximum frequency.

The exact implementation should follow the published definition rather than inventing a new geometric criterion.

Add diagnostics showing:

```text
original spectrum
integrated spectrum
reference geometry
detected envelope
```

This is essential because GM can fail in recognizable ways.

Li et al. report that GM/MGM performance depends on whether the integrated power spectrum resembles the assumed characteristic shape and that GM/MGM can overestimate maximum velocity. ([MDPI][4])

# 11. Estimator 6 — SNSI

Implement **Signal-Noise Slope Intersection (SNSI)**.

The conceptual model is:

```text
signal region
      \
       \
        \ transition
         \
          \ noise floor
```

Estimate the signal and noise slopes and identify their intersection.

Use this as a direct implementation of the published algorithm.

Reference:

Kathpalia et al., *Adaptive Spectral Envelope Estimation for Doppler Ultrasound*, IEEE TUFFC, 2016. DOI 10.1109/TUFFC.2016.2587381. ([PubMed][1])

Important experiment:

Vary the SNSI parameters systematically.

Do not report a single SNSI result without documenting:

* smoothing;
* slope-window size;
* noise-floor estimator;
* minimum signal range;
* search limits.

# 12. Estimator 7 — modified/adaptive SNSI

This should be one of the main classical competitors.

Implement the method from:

**Kathpalia et al., 2016 — Adaptive Spectral Envelope Estimation for Doppler Ultrasound.**

The method modifies SNSI and incorporates aspects of an altered GM, with adaptive noise estimation from the spectrogram. The authors tested it on simulations, phantom data and several in-vivo vascular datasets. ([PubMed][1])

Implement it as faithfully as practical.

The key idea is:

```text
estimate noise
      ↓
estimate signal/noise transition
      ↓
determine maximum-frequency point
      ↓
smooth envelope
```

This is likely to be one of the strongest **spectrum-based** methods in the benchmark.

# 13. Estimator 8 — QIA

Implement the **Quadratic Iteration Algorithm (QIA)** from Li et al. 2019.

Reference:

J. Li et al., *A Robust Automatic Ultrasound Spectral Envelope Estimation*, Information, 2019, 10(6), 199. DOI 10.3390/info10060199. ([DOI][5])

The paper proposes QIA based on the integrated power spectrum and compares it against MGM and MSNSI. It specifically investigates robustness to added noise and reports applicability to negative-flow conditions. ([MDPI][4])

Implement:

```python

```

and document every parameter.

Important benchmark:

Measure computational cost as well as accuracy.

The paper reports QIA as approximately \(O(2N)\), compared with \(O(N)\) for MGM/MSNSI. ([DOI][5])

For a single DICOM frame this is unlikely to matter much, but it is useful if this eventually becomes real-time software.

# 19. Boundary extraction methods

Implement several.

## E1 — outermost occupied pixel

For each x:

$$
e(x)=\max\{y:M(x,y)=1\}.
$$

Baseline method.

---

## E2 — biggest contiguous vertical region

For each x:

1. find contiguous foreground runs;
2. select the largest/most plausible run;
3. use its upper boundary.

This is directly motivated by the family of image-processing envelope methods analyzed by Sulas et al. ([PubMed Central (PMC)][2])

---

## E3 — largest component boundary

Extract the boundary of the selected connected component.

---

## E4 — maximum-gradient boundary

Calculate:

$$
G_y = |\partial I/\partial y|
$$

and search for the strongest outward edge around the candidate signal region.

This should be treated as an experimental method rather than a direct literature reproduction.

# 20. Temporal/spatial curve optimization

This is the component I expect to make the biggest difference.

Rather than independently estimating:

$$
e_1,e_2,\ldots,e_N
$$

solve for an entire curve:

$$
\mathbf e^*
=
\arg\max_{\mathbf e}
\sum_x S(x,e_x)
-\lambda\sum_x|e_x-e_{x-1}|
-\mu\sum_x|e_x-2e_{x-1}+e_{x-2}|.
$$

Here:

* \(S(x,y)\) = likelihood that pixel \((x,y)\) belongs to the envelope;
* first-order term penalizes jumps;
* second-order term penalizes excessive curvature.

Implement dynamic programming.

This is still a classical optimization algorithm, not machine learning.

### Why this is attractive

The envelope is physically/physiologically expected to be continuous.

Noise is not.

Therefore:

```text
noisy image
      ↓
pixel likelihood
      ↓
global constrained curve
```

should outperform:

```text
noisy image
      ↓
independent max per column
```

particularly at low SNR.

---

# 22. Latham-style Otsu/morphological method

This deserves its own named implementation rather than merely being included as “Otsu + morphology.”

Reference:

Latham et al., *Stable Automatic Envelope Estimation for Noisy Doppler Ultrasound*, IEEE TUFFC 2021, 68(3), 465–481, DOI 10.1109/TUFFC.2020.3011823. ([PubMed][3])

The published method is specifically designed to produce stable envelopes under high noise and variable envelope shape.

It was tested using:

* simulated pulsatile flow;
* a flow phantom;

Because your input is already an image, this method is particularly relevant.

Implement it as faithfully as possible from the publication, but clearly document which parts cannot be reproduced because you don't have the original Doppler audio.

# 26. Evaluation metrics

Do **not** rely on one metric.

Use at least five.

## 26.1 Mean absolute envelope error

$$
MAE =
\frac{1}{N}
\sum_x
|\hat e(x)-e_\mathrm{ref}(x)|.
$$

Report pixels and normalized velocity units.

---

## 26.2 RMSE

$$
RMSE =
\sqrt{
\frac1N
\sum_x
(\hat e(x)-e_\mathrm{ref}(x))^2
}.
$$

RMSE exposes occasional catastrophic excursions.

---

## 26.3 Relative error

$$
RE =
\frac{|\hat e-e|}
{|e|+\epsilon}.
$$

Be careful around zero velocity.

For that reason, calculate relative error only where:

$$
|e| > e_\mathrm{min}.
$$

---

# 27. Clinically relevant derived metrics

For each waveform calculate:

### Peak velocity

$$
V_\mathrm{max}=\max_x e(x).
$$

Compare:

$$
|\hat V_\mathrm{max}-V_\mathrm{max}|.
$$

### Mean velocity

If meaningful for the modality.

### VTI

$$
VTI=\int e(t)\,dt.
$$

This should be a major metric for cardiac spectral Doppler.

### Timing

Measure:

* onset;
* peak;
* end;
* duration.

This is especially important because an envelope that is visually reasonable can still produce poor timing.

$$

$$

$$

Therefore report:

# 29. Bland–Altman analysis

For clinically meaningful scalar quantities:

* Vmax;
* VTI;
* EDV;
* PSV if applicable;

generate Bland–Altman plots.

Calculate:

$$
d_i=\hat y_i-y_i
$$

and

$$
\bar y_i=\frac{\hat y_i+y_i}{2}.
$$

Report:

# 30. Envelope coverage metrics

Introduce:

### Overestimation fraction

$$
F_\mathrm{over}
=
\frac{
\#\{x:\hat e(x)>e(x)+\delta\}
}{N}.
$$

### Underestimation fraction

$$
F_\mathrm{under}
=
\frac{
\#\{x:\hat e(x)<e(x)-\delta\}
}{N}.
$$

This is useful because different algorithms have characteristic bias.

For example, GM/MGM can have a tendency toward overestimation according to Li et al. ([MDPI][4])

---

# 31. Smoothness metrics

Calculate:

$$
S_1=
\frac1{N-1}
\sum_x
|\hat e_{x+1}-\hat e_x|
$$

and

$$
S_2=
\frac1{N-2}
\sum_x
|\hat e_{x+2}-2\hat e_{x+1}+\hat e_x|.
$$

These quantify:

* jitter;
* excessive curvature.

But **do not optimize purely for smoothness**.

A perfectly smooth waveform can be physiologically wrong.

# 39. Important issue: spectral broadening

This is fundamental.

The outermost visible spectral boundary is not necessarily the true maximum physical velocity.

Therefore distinguish:

```text
image envelope
```

from:

```text
physical maximum velocity
```

The literature explicitly identifies intrinsic spectral broadening as a source of maximum-velocity estimation error. ([PubMed][1])

For the initial benchmark, use the expert's trace as the target.

Do not claim physical ground truth unless phantom/reference-flow information is available.

# 40. Important issue: image compression and rendering

Since the input is DICOM image data, determine whether:

* logarithmic compression;
* dynamic range;
* grayscale mapping;
* interpolation;
* JPEG compression;
* annotations;
* display LUTs

have modified the original spectral intensities.

This means:

> Integrated power calculated from image grayscale is only a proxy for actual Doppler power.

Therefore GM/MGM/QIA/SNSI should be treated as **image-domain adaptations**, not mathematically identical reproductions of the original signal-domain algorithms.

This distinction must be documented in the code and report.

# 41. Important issue: pixel aspect ratio

Do not treat:

```text
1 pixel x
```

as equivalent to:

```text
1 pixel y
```

The x-axis represents time and the y-axis represents velocity/frequency.

Morphological kernels should therefore be interpreted in physical coordinates where possible.

For example:

```python

kernel_height_velocity
```

should eventually be converted into pixels.

This will make the algorithm much more robust.

# 53. Expected outcome / hypothesis

Before running the experiment, put the following into the project README as a **pre-registered hypothesis**.

### Hypothesis H1

At high SNR, classical spectrum-based methods—especially adaptive SNSI/GM and QIA—will be competitive with image-based methods.

### Hypothesis H2

At decreasing SNR, image-based methods will degrade more gracefully because they exploit spatial continuity.

### Hypothesis H3

A global curve-tracking formulation will outperform independent-column estimators at low SNR.

### Hypothesis H4

The same overall detector architecture can be used for spectral Doppler and TDI, but optimal preprocessing/regularization parameters will differ.

### Hypothesis H5

The best practical solution will likely be a **hybrid image-domain method**, approximately:

```text
adaptive background estimation
        ↓
contrast normalization
        ↓
Otsu/adaptive segmentation
        ↓
morphological cleanup
        ↓
candidate boundary likelihood
        ↓
dynamic-programming envelope tracking
        ↓
light temporal smoothing
```

rather than pure GM/MGM/SNSI.

This hypothesis is motivated by the low-SNR results reported by Latham et al. and by the systematic image-processing analysis of Sulas et al., but should be treated as an empirical hypothesis for this particular single-vendor DICOM dataset. ([PubMed][3])

# 54. One particularly important experiment

I would make this the centerpiece of the project:

## "Does 2-D information actually help?"

For every image calculate:

### Method A

Independent column-wise estimate:

$$
\hat e_t=f(I_t)
$$

### Method B

Column-wise estimate + 1-D smoothing:

$$
\hat e_t=\mathrm{smooth}(f(I_t))
$$

### Method C

2-D image segmentation:

$$
M(x,y)
$$

followed by boundary extraction.

### Method D

2-D likelihood + globally optimized curve:

$$
\hat e=
\arg\max_e
\left[
\sum_x S(x,e_x)
-\lambda R(e)
\right].
$$

Then plot performance against SNR.

If C/D substantially outperform A/B at low SNR, that provides strong evidence that the correct abstraction for your application is **image segmentation/tracking rather than spectral maximum estimation**.

# 60. What I expect to be the eventual winner

I would **not** start the project assuming QIA, SNSI, GM or Otsu is the final solution.

For your particular constraints—**single-vendor, single-frame rendered DICOM, both spectral and tissue Doppler, varying SNR**—my working hypothesis would be:

> **A carefully designed 2-D image-domain detector with adaptive background estimation + robust binarization + morphology + connected-component filtering + constrained curve tracking is the most likely overall winner.**

More specifically, I would expect:

```text
High SNR:
    GM / adaptive SNSI / QIA
        ≈
    image-based method

Medium SNR:
    adaptive SNSI / QIA
        ≈
    robust image method

Low SNR:
    robust image method
        >
    independent spectrum estimators
```

and I would expect the **dynamic-programming curve tracker** to be particularly useful for the lowest-SNR cases.

The key reason is that your problem is not really "estimate maximum frequency from a power spectrum." Once the ultrasound system has rendered the spectrum into a DICOM image, your problem becomes:

$$
\boxed{
\text{find the most probable continuous Doppler-energy boundary in a noisy 2-D image}
}
$$

That formulation naturally accommodates both spectral Doppler and TDI, whereas GM/SNSI/QIA are more tightly tied to assumptions about a one-dimensional power spectrum.

One caveat is important: Latham's published algorithm derives its spectrogram from Doppler audio rather than from an already-rendered ultrasound screenshot/DICOM, specifically to avoid device-dependent image-rendering effects. ([PubMed][3]) Therefore, in your project I would treat it as an **important conceptual and algorithmic benchmark**, not assume that a literal implementation will reproduce its published performance on your DICOM frames.

Finally, I would have Claude produce **both the implementation and a research-style benchmark report**. The report should automatically answer, from your actual data, three questions: **(1) which estimator is most accurate, (2) how the ranking changes with SNR, and (3) whether one common detector really works for spectral and tissue Doppler.** That will be considerably more informative than selecting an algorithm from the literature a priori.
